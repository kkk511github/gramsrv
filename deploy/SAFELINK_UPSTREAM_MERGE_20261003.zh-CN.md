# SafeLink 上游合并说明：2026-10-03

本次将上游 `iamxvbaba/gramsrv` 的 `main`（`09ff5105`）合并到 SafeLink 的 `dev`。这是源码合并记录，不代表已 push 或部署到生产。

## 新增与修复

- 设备位置：可通过 `TELESRV_GEOIP_ENDPOINTS` 配置有序的 IP 归属解析后端，新增缓存、负缓存、并发限制、超时和后端熔断。查询基于真实会话 IP，不根据手机号推测。私有及保留地址不会发送给这些 HTTP 后端。
- 机器人 Stars 钱包：机器人收取的 XTR 发票款项记录到独立的机器人余额中，`payments.getStarsRevenueStats` 可以读取机器人收益，不与普通用户余额混用。这是当前自托管实例的账本，不是官方 Telegram 的资金账户。
- 机器人发票：持久化发票作为结算依据，支持发送 XTR 发票、支付前 `pre_checkout_query` 校验、成功支付通知和可重试退款。支付前需要机器人响应，不能只发送发票后就假设支付成功。
- Bot API 更新队列：提供 `drop_pending_updates` 清理旧更新的能力，并补齐支付前询问消息的队列结构。
- 机器人命令识别：Bot API 消息中的 `/command`、`/command@bot` 增加命令实体，便于机器人框架识别处理器。

## SafeLink 兼容处理

- 保留设备页中的 SafeLink 客户端名称、真实 IP 和 iOS 当前设备 `hash = 0` 约定。
- 没有配置新 GeoIP 后端时，继续使用现有中文 IP 位置解析器；配置新后端后只走所配置的解析链，不额外调用旧提供商。
- 位置查询按会话列表批量处理并限制总时间。无法解析时保留 `Unknown`，不伪造地理位置。
- 保留现有注册、五位可见邀请码、注册时设置密码及退出后凭证登录策略。

## 下次部署必须注意

当前 SafeLink 已有迁移执行到 `0222`。上游新增的 `0212–0215` 与历史 SafeLink 迁移编号重复，不能直接使用这些编号：数据库可能跳过它们，启动后缺少机器人支付表。

本次已保留历史迁移不变，将四项新增迁移顺延为：

| SafeLink 编号 | 内容 | 上游原编号 |
| --- | --- | --- |
| `0223` | 机器人 Stars 钱包及收款凭据 | `0212` |
| `0224` | 机器人发票 | `0213` |
| `0225` | 支付前询问消息载荷 | `0214` |
| `0226` | 支付前询问消息索引和结构约束 | `0215` |

部署前备份数据库，在隔离的测试数据库验证从 `0222` 升到 `0226`；不要将迁移版本直接强制标为 `0226`。部署后检查迁移版本与 dirty 状态，测试机器人支付、退款及原有登录流程。

GeoIP 多后端是可选项，本次合并不自动改生产环境配置。启用前应评估会话 IP 发往第三方提供商的隐私影响，必要时使用自托管解析服务。
